## Ambiente e convenções (OBRIGATÓRIO)
- SO: Windows → PowerShell 5.1. `rg` NÃO existe — usar ferramenta Grep p/ busca de conteúdo.
- Build/teste: `.\gradlew.bat test --console=plain` (nunca `./gradlew`). Rodar com `--rerun-tasks`
  quando mudar migrations/DB. Se `JAVAFX_MODULES_HOME` não estiver definida, tasks como `run`
  falham — mas `test`/`compileJava` funcionam.
- Padrão de tela: `Screen` + `ViewModel` em `my_app/screens/<entidade>/`;
  CRUD de listagem usa `ContratoTelaCrudV3`/`ViewModelScreenContract`.
- Camada de dados: `Model` (Persism) + `Repository` (`BaseRepository`) + `Service` (`BaseService`),
  em `my_app/db/`. Validações de domínio ficam no Service (padrão já estabelecido).
- Regras de UI: mensagens de erro amigáveis pro usuário; detalhe técnico só em `log.error`.
- **NUNCA editar via PowerShell `Set-Content`** (codificação ANSI corrompe UTF-8 — já aconteceu;
  usar as ferramentas Write/Edit). Testes de repo usam banco em memória POR CLASSE
  (`testUrl()` → `testdb-<Classe>?mode=memory&cache=shared`).
- Front de teste padrão do fake server: `com.sun.net.httpserver` (câmera) e `ServerSocket` em
  loopback com porta efêmera (balança) — sem lib nova.
- Docs de manutenção a atualizar a cada mudança: `docs/TODO.md` (marcar item com `[x]` + nota
  "**Corrigido: ...**"), `docs/CONTEXT.md` ("Estado atual"), `docs/DECISIONS.md` (decisão com
  Contexto/Decisão/Testado).
- Não commitar sem pedido explícito. No commit: mensagem curta no estilo do repo (ex.:
  `fix:`, `feat:`, `refactor:`, `clean:`), stage só do que for intencional.
